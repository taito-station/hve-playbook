# review-doc

文章・ドキュメントのレビューを行うスキル。4つの観点を並列エージェントで同時にレビューし、高速化する。

## レビューの基本姿勢

書き手の最善の努力を尊重し、**相手のことを考える**ことを根底に置く。

- **肯定的な表現**で指摘する（指示・命令ではなく提案として書く）
  - NG: 「この書き方はわかりづらい」「ここは間違っている」
  - OK: 「このように書くと、さらにわかりやすくなりそうです」「〜と書くのはいかがでしょうか」
- 良い点があれば積極的に言及する

## 優先度ラベル（4段階）

| ラベル | 意味 | 使いどころ |
|---|---|---|
| `must` | 必ず対応する | 事実誤認・コードが動作しない・読者を誤誘導する記述 |
| `should` | 可能であれば対応する | 構成上の重要な改善・誤解を招きやすい表現 |
| `nits` | 細かい指摘 | 誤字脱字、表記ゆれ、軽微なフォーマット |
| `imo` | in my opinion。このままでもよいが、自分だったらこう書く | 表現の好み・代替案の提示。対応は任意 |

## Instructions

### 引数

- `$ARGUMENTS` にファイルパスまたはURLが指定された場合、それを対象にレビューする
- 複数ファイルが指定された場合、すべてを対象にレビューする

### 手順

#### ステップ1: ドキュメントの取得

- ファイルパスの場合：Readツールでファイルを読み込む
- URLの場合：WebFetchで取得する
- 対象ファイルの種類（Markdown, テキスト, RST, etc.）を判別する

#### ステップ2: 4つのエージェントを並列起動

Agent ツールで以下の4つのエージェントを **すべて同時に（1つのメッセージで）** 起動する。
各エージェントには `subagent_type: "general-purpose"` 、 `model: "haiku"` を指定する。
各エージェントのプロンプトには、ステップ1で取得したドキュメントの全文を含める。

各エージェント共通の指示として、以下を必ず含める：

- 指摘は**肯定的・提案形**で書く（命令調を避ける）
- 優先度は `must` / `should` / `nits` / `imo` から選ぶ（定義は本SKILL.mdの「優先度ラベル」を参照）
- `must` / `should` には必ず修正後の文面を添える
- `imo` は「自分だったらこう書く」という代替提案。対応強制ではないことが伝わる文面にする

**エージェント1: 正確性・整合性チェック**
```
以下のドキュメントをレビューし、正確性・整合性の観点のみで問題を検出してください。

検出対象：
- 事実誤認や矛盾する記述
- コード例がある場合、構文エラーや動作しないコードの検出
- バージョン番号やリンク先の整合性
- 用語の定義と使用の一貫性

レビュー方針：
- 指摘は肯定的・提案形で書く
- 優先度は must / should / nits / imo の4段階
  - must: 事実誤認・動作しないコードなど、読者を誤誘導する問題
  - should: 整合性を高めるために対応したい事項
  - nits: 軽微な不整合
  - imo: より明確にするための代替案

出力形式（各指摘ごと）：
- priority: must / should / nits / imo
- location: 該当箇所の引用（原文をそのまま引用）
- description: 指摘内容（肯定的表現）
- suggestion: 修正案または代替案（must/should は必須、修正後の文面を含む）

問題がなければ「指摘なし」と返してください。

---
ドキュメント:
<ドキュメント全文>
```

**エージェント2: 構成・論理展開チェック**
```
以下のドキュメントをレビューし、構成・論理展開の観点のみで問題を検出してください。

検出対象：
- 文書全体の構成は論理的か
- セクション間の流れは自然か
- 重要な情報の欠落はないか
- 冗長な繰り返しや不要なセクションはないか

レビュー方針：
- 指摘は肯定的・提案形で書く（「論理が飛躍している」ではなく「ここに一文挟むとつながりが見えそう」）
- 優先度は must / should / nits / imo の4段階
  - must: 重要情報の欠落・読者が誤解する構成
  - should: 構成を整えるとさらに読みやすくなる箇所
  - nits: 軽微な順序入れ替えなど
  - imo: 別の構成案の提示

出力形式（各指摘ごと）：
- priority: must / should / nits / imo
- location: 該当箇所の引用（原文をそのまま引用）
- description: 指摘内容（肯定的表現）
- suggestion: 修正案または代替案（must/should は必須、修正後の文面を含む）

問題がなければ「指摘なし」と返してください。

---
ドキュメント:
<ドキュメント全文>
```

検出対象：

- 曖昧な表現や誤解を招く記述
- 主語と述語の対応、係り受けの明確さ
- 一文が長すぎないか
- 専門用語の適切な説明

レビュー方針：
- 指摘は肯定的・提案形で書く（「わかりづらい」ではなく「こう書くとさらにわかりやすくなりそう」）
- 優先度は must / should / nits / imo の4段階

  - should: 改善するとぐっと読みやすくなる箇所
  - nits: 軽微な言い回し
  - imo: より洗練された言い回しの代替案

出力形式（各指摘ごと）：
- priority: must / should / nits / imo
- location: 該当箇所の引用（原文をそのまま引用）
- description: 指摘内容（肯定的表現）
- suggestion: 修正案または代替案（must/should は必須、修正後の文面を含む）

**エージェント4: 形式・体裁チェック**
```
以下のドキュメントをレビューし、形式・体裁の観点のみで問題を検出してください。

検出対象：
- Markdownの構文エラー（見出しレベル、リンク、コードブロック）
- 誤字脱字
- 表記ゆれ（漢字/ひらがな、英数字の全角/半角）
- フォーマットの一貫性

レビュー方針：
- 指摘は肯定的・提案形で書く
- 優先度は must / should / nits / imo の4段階
  - must: レンダリング崩れなど読者に支障が出る問題
  - should: 一貫性を整えると読みやすくなる事項
  - nits: 誤字脱字・表記ゆれなど（このカテゴリは多くが nits）
  - imo: 表記の代替案

出力形式（各指摘ごと）：
- priority: must / should / nits / imo
- location: 該当箇所の引用（原文をそのまま引用）
- description: 指摘内容（肯定的表現）
- suggestion: 修正案または代替案（must/should は必須、修正後の文面を含む）

問題がなければ「指摘なし」と返してください。

---
ドキュメント:
<ドキュメント全文>
```

#### ステップ3: 結果の集約と出力

4つのエージェントの結果を集約し、以下のフォーマットで出力する：

```
## ドキュメントレビュー: <ファイル名またはタイトル>

### サマリー
<文書の概要と全体的な評価を1-3文で。可能なら良い点も触れる>

### 指摘事項

#### 🔴 must（必ず対応）
- **[観点]** 該当箇所の引用 → 指摘内容と修正案

#### 🟡 should（可能であれば対応）
- **[観点]** 該当箇所の引用 → 指摘内容と修正案

#### 🟢 nits（軽微）
- **[観点]** 該当箇所の引用 → 指摘内容

#### 💭 imo（このままでもよいが、自分ならこう書く）
- **[観点]** 該当箇所の引用 → 代替案の提示

### 良い点
<特筆すべき良い点があれば記載>
```

- 指摘が無いセクションは省略する
- 重複する指摘はマージする
- 優先度順（must → should → nits → imo）で並べる
- `must` には必ず修正後の文面を提示する
- 文面は肯定的・提案形に統一する（命令調を避ける）
