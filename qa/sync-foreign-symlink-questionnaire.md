## サマリー

sync-dotclaude.sh は、別の場所を指す既存の symlink（CLAUDE.md・statusline.sh・各 skill/hook など）と symlink の settings.json を、退避も警告もせずに置き換える。実体の同名ファイルは WARN でスキップ（exit 2）なので、symlink のときだけ扱いが軽い。利用者が気づけて戻せるようにする方式を決める。

[Q01]
- 対象ドキュメント: sync-dotclaude.sh
- 該当箇所: link_one（57〜74 行目）
- 問題種別: 重大な欠落
- 重大度: major
- 質問内容: 別の場所を指す symlink を見つけたとき、どう扱いますか？
- 選択肢: A) (a)+(b) 張り替える。WARN に元のリンク先と戻すコマンド（ln -sfn <元> <リンク>）を出し、exit 2 にする B) (b) 張り替える。WARN と exit 2 に加え、元のリンク先を ~/.claude 内の記録ファイルにも追記する C) (c) 実体と同じくスキップする（WARN と exit 2。張り替えない） D) (a) 張り替えて WARN と exit 2 にするだけ（元のリンク先は出さない）
- 未回答時の既定値候補: (a)+(b) 張り替える。WARN に元のリンク先と戻すコマンド（ln -sfn <元> <リンク>）を出し、exit 2 にする
- 既定値候補の理由: WARN と exit 2 で気づけ、出力に元のリンク先が残るので戻せる。張り替えるので sync の目的（リポ版を効かせる）も果たせる。次回の sync からは正しいリンクなので静かに通る。記録ファイルを足さないので最小
- 未回答のまま進めた場合の影響: 第三者が dotfiles で管理しているリンクが、気づかないうちにリポへのリンクに置き換わる

[Q02]
- 対象ドキュメント: sync-dotclaude.sh
- 該当箇所: link_one の readlink の比較
- 問題種別: 不明瞭
- 重大度: major
- 質問内容: 「別の場所を指す」とみなすリンクの範囲はどうしますか？
- 選択肢: A) このリポ（REPO_DIR）の外を指すリンクを対象にする。リポ配下を指すリンクは今までどおり静かに張り直す（旧 clone・別 clone を指すリンクは対象に入る） B) 別の hve-playbook の clone を指すリンクも静かに張り直し、それ以外だけを対象にする C) リポ配下を含め、張り直すリンクはすべて対象にする
- 未回答時の既定値候補: このリポ（REPO_DIR）の外を指すリンクを対象にする。リポ配下を指すリンクは今までどおり静かに張り直す（旧 clone・別 clone を指すリンクは対象に入る）
- 既定値候補の理由: dangling 検査（5）と同じ「REPO_DIR 配下か」の判定で揃えられる。別 clone から sync したことにも気づける（一度だけの WARN で済む）
- 未回答のまま進めた場合の影響: 範囲が広すぎると作者の通常の同期で WARN が出続け、狭すぎると第三者のリンクを黙って置き換える

[Q03]
- 対象ドキュメント: sync-dotclaude.sh
- 該当箇所: settings.json の配置（290〜292 行目）
- 問題種別: 一貫性欠落
- 重大度: major
- 質問内容: settings.json が symlink のときも同じ扱いにしますか？
- 選択肢: A) 同じ扱い: リポの settings.json を指すものは今までどおり静かに migrate、それ以外は WARN に元のリンク先を出して exit 2（リンク先は変えない） B) それ以外のときは、リンク先の中身を settings.json.bak-<日時> にコピーして退避してから置き換える（実体の直接編集と同じ退避） C) それ以外のときは置き換えずにスキップする（settings.json は配置しない）
- 未回答時の既定値候補: 同じ扱い: リポの settings.json を指すものは今までどおり静かに migrate、それ以外は WARN に元のリンク先を出して exit 2（リンク先は変えない）
- 既定値候補の理由: Q01・Q02 と規則が揃い、作者の旧方式の移行（テスト h11）は今までどおり通る
- 未回答のまま進めた場合の影響: settings.json だけ扱いがずれる

[Q04]
- 対象ドキュメント: sync-dotclaude.sh
- 該当箇所: 引数の解析（42〜48 行目）
- 問題種別: 不明瞭
- 重大度: minor
- 質問内容: --prune やほかのフラグとの関係はどうしますか？
- 選択肢: A) 新しいフラグは足さない。--prune の対象も変えない B) 挙動を切り替えるフラグ（例: スキップにする・黙って張り替える）を足す
- 未回答時の既定値候補: 新しいフラグは足さない。--prune の対象も変えない
- 既定値候補の理由: WARN は張り替えた回の一度だけで、止めるためのフラグの需要が無い（YAGNI）。--prune は対象が重ならない
- 未回答のまま進めた場合の影響: フラグを増やすと保守とテストが増える
